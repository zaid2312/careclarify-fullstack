# CareClarify Backend

A FastAPI backend that adds **real AI-powered bill analysis** to the CareClarify frontend.
Upload a photo, PDF, or pasted text of a hospital bill and get back an itemized audit —
fair-price estimates, overcharge flags, and regulatory-cap violations — generated by Claude.

No database, no user accounts (by design) — this is a single stateless endpoint. The
frontend's "simulated patient case" buttons still work locally with zero backend involvement;
only real uploads/drag-drop hit this API.

## 1. Setup

```bash
cd careclarify-backend
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

Copy the env file and add your Anthropic API key (get one at https://console.anthropic.com/):

```bash
cp .env.example .env
# then edit .env and set ANTHROPIC_API_KEY=sk-ant-...
```

## 2. Run it

```bash
uvicorn app.main:app --reload --port 8000
```

The API is now live at `http://localhost:8000`. Interactive docs (Swagger UI) are at
`http://localhost:8000/docs` — good for testing uploads directly in the browser.

## 3. Connect the frontend

In `app.js` (in the frontend project), `API_BASE_URL` is already set to
`http://localhost:8000`. If you run the backend elsewhere, update that constant.

Then just open `index.html` (or serve the frontend folder with any static server) — dragging
a file into the upload zone or clicking "Browse Files" now sends it to this backend for real
analysis. The three "simulated patient case" buttons remain local demos and don't call the API.

## 4. How it works

`POST /api/analyze-bill` accepts a multipart form with either:
- `file`: a JPEG/PNG photo of the bill, a text-based PDF, or a `.txt` file, or
- `text`: pasted bill content as a plain string

For images, the raw image is sent to Claude's vision API. For PDFs, text is extracted with
`pdfplumber` first (scanned/image-only PDFs without a text layer aren't supported — ask the
user to upload a photo instead). The extracted content is sent to Claude with a system prompt
that knows about Indian hospital billing norms (NPPA implant price caps, typical room-rent and
consultation bands, generic-vs-brand pharmacy pricing, duplicate-billing patterns) and asks it
to return structured JSON: line items with fair-price estimates, categories, and statuses, plus
a short list of top findings.

Totals and the chart-data breakdown are computed server-side from the model's line items
(not trusted from the model directly), then validated against a strict Pydantic schema before
being returned — so the response always matches the shape the frontend expects.

## 5. Notes & next steps

- **Cost/rate limits**: each analysis is one Claude API call. Consider adding request
  size limits and basic rate limiting before deploying publicly.
- **Accuracy**: the model's fair-price estimates are informed guesses grounded in general
  billing norms, not a live regulatory database — treat them as a starting point for a
  patient's own dispute, not a legal audit.
- **Deploying**: this is a plain ASGI app — deploy it anywhere that runs Python (Render,
  Railway, Fly.io, a VPS with `uvicorn`/`gunicorn`, etc). Set `FRONTEND_ORIGINS` in `.env` to
  your deployed frontend's URL(s) for CORS once you're not just running locally.
- **Optional future additions**: move the prescription database and procedure-cost tables
  (currently hardcoded in the frontend's `app.js`) into this backend too, so they can be
  updated without redeploying the frontend. Happy to help with that next if useful.
